# YiTatro 网站改版设计与实现方案

v1.0 · 2026-11-17 · 黑白方案 · 仓库基线 main / cdeeb52

这份文件供设计、实现和审核使用。方案以性能为第一优先级，品牌使用 **YiTatro**，域名拼写按 **yitatro** 记录，后缀和发布地址由项目负责人确定。首页保留「先看到太极，向上滑进入站点」的操作；专厅、工具、文章和牌义从链接直达。英语用户可以先完成一个熟悉的工具，再从结果发现另一种解读方式。

## 1. 技术选型

| 用途 | 技术 | 应用边界 |
|---|---|---|
| 页面和路由 | 现有 Next.js App Router、React、TypeScript | 沿用项目锁定版本和现有路由。静态标题、页面框架、专厅链接和文章优先由服务端组件输出。菜单、表单、牌堆、掷币和用户状态采用独立客户端组件。 |
| 样式和布局 | Tailwind CSS 4、CSS 自定义属性、Grid / Flex | 共用主题值和基础组件。使用语义 HTML 表单、按钮、链接、列表和标题。现有图标可复用 Lucide；太极使用已有矢量图形。 |
| 首页动效 | 现有 GSAP、@gsap/react、ScrollTrigger | GSAP 控制太极和题句的上移与淡出。注册范围限制在首页开屏，离开页面后清理。按钮、焦点、菜单等短反馈用 CSS。已有抽牌和掷币动效按各自路由加载。 |
| 桌面滚轮 | Lenis，作为唯一计划新增的运行时依赖 | 仅桌面首页启用。使用一个实例，由 GSAP ticker 驱动；设置自动帧循环关闭，避免第二个循环。触控保持原生；开启减少动态效果时回到原生滚动。 |
| 图片和字体 | 现有太极 SVG、站内塔罗资源、next/image、系统字体 | 使用原有牌图，按版位尺寸请求和预留比例。字体优先用平台回退；如果固定品牌标题确实需要自托管字体，用许可允许的小子集。先把全局远程字体请求从首屏路径移开，再复测实际字体请求。 |
| 业务 | 已有工具逻辑、接口、登录和积分 | 统一界面组件，复用现有输入校验、计算和接口。图稿中的字段、会员栏位、卡牌状态文案只用于说明布局；开发前逐页映射真实行为。 |

参考：[Next.js 服务端与客户端组件](https://nextjs.org/docs/app/getting-started/server-and-client-components) · [GSAP React](https://gsap.com/resources/React/) · [Lenis 与 ScrollTrigger 官方集成](https://github.com/darkroomengineering/lenis#gsap-scrolltrigger)。实现前用仓库锁定版本的 Next.js 本地文档核对 API。

## 2. 视觉规范

| 用途 | 色值 |
|---|---|
| 页面底色及按钮文字 | 白色 #FFFFFF |
| 字标、标题、正文、主按钮、太极深色 | 近黑 #171717 |
| 说明、辅助文字 | 深灰 #52525B |
| 表单控件边界 | 灰色 #8A8A91 |
| 分隔线、装饰边框 | 浅灰 #E4E4E7 |
| 轻微选中底色、结构占位 | 浅灰底 #F5F5F6 |

- 页面留白靠版式建立层次。页面标题用宋体 / Georgia 等衬线回退，表单、导航、正文用系统无衬线。桌面首页标题建议从 48–60px 打样，工具标题 32–40px；手机工具标题 26–32px，正文 16px 起。以真实中英文和系统放大效果为准。
- 导航和内容共享左右基线，桌面主栏最大约 1200px，长文保持适合阅读的窄栏。按钮用黑底白字，次操作用边框或下划线；同一任务优先突出一个主操作，首页东西入口等权。
- 塔罗牌保留原色作为内容。太极、爻线和铜钱用黑白表现。选中、错误、完成状态同时通过描边、文字或图标表达；键盘焦点要明显可见。

顶部导航统一为 **易经与八字 / 塔罗 / 指南**（**I Ching & BaZi / Tarot / Learn**）。桌面左侧 YiTatro 字标，中间分类，右侧语言和账户。手机菜单内提供 **English / 简体中文**。首页封面只有轻量字标及语言入口；完整导航到双入口区才出现。内页始终能识别所属分类，搜索或外部链接打开内页不会先跳回太极。页脚和账户都可承接会员入口。

中文首页用「易有太极，是生两仪」和说明「周易、八字与塔罗」，英文首页用 **I Ching, BaZi & Tarot**。每个语言版本使用对应文案，保留完整的表单提示、错误、加载、空态和结果。切换语言时匹配对应页面与原有路由参数。核对页面语言声明、canonical、hreflang、分享信息、站点地图与品牌名；域名确定后统一处理绝对地址。已有对外旧域时，再单独核对旧链接重定向。参考 [Google 多语言站点指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)。

英语用户首次遇到 BaZi 时，用一句话说明它是根据出生日期和时间排出的命盘。只为现有功能实际支持的出生时间、时区和输入方式写提示。需要登录或积分的操作在开始前明示。在塔罗结果后可提供易经入口，易经结果后可提供抽一张牌入口；只在用户主动操作时进入另一工具。

## 4. 开屏和动效

1. 首次渲染时太极、题句和入口提示就位。封面和双入口是一条连续的文档流，主要文字与链接先可访问。封面用小视口高度作为最小高度，内容较长时允许自然增高，避免横屏、地址栏变化或字体放大时截断。[CSS 视口长度单位](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)
2. 移动端向上滑，桌面向下滚动页面，都自然看到第二屏。可点击和键盘操作的入口指向同一个锚点；对齐导航高度，并在主动跳转时给入口标题可见焦点。普通滚动无需改焦点。动画未就绪时同样能到达。
3. 到入口区之前，ScrollTrigger 只根据滚动进度更新太极及题句的位移、不透明度。先用约一屏滚动打样，回滚可逆；首屏不设挡住滚动的等待时间。只有在确实需要固定构图时才考虑 CSS sticky，保持入口区在文档流中。
4. 首页桌面启用 Lenis 时，由 GSAP ticker 传毫秒给 Lenis，Lenis 滚动事件更新 ScrollTrigger。触控保持原生，菜单和可独立滚动的面板保持本身的滚动，读者返回、锚点和键盘操作都必须正确。路由卸载、媒体条件切换时销毁 Lenis、移除 ticker 并还原动画。选用实际手感与生产构建对照通过的配置。
5. 移动端用原生滚动。减少动态效果时关掉滚动联动，保留完整页面和点击入口。所有页面避免每张卡逐个淡入、长时间背景循环、首屏视频和为滚动另建渲染层。

## 5. 响应式和输入方式

| 检查尺寸（CSS px） | 首页及导航 | 表单、卡牌和结果 |
|---|---|---|
| 320 / 390 宽手机 | 两侧入口上下排，菜单收起。常见手机高度下尽量让两入口都可见；矮屏正常滚动。 | 单列顺序为标题、输入、主按钮、结果。牌阵选择支持点击；较宽盘面只在自身区域局部滚动，并给出提示。 |
| 768 / 820 宽平板竖屏 | 内容边距约 24–32px。两侧入口在英文标题和点击区都放得下时并排，否则上下排。保留菜单入口。 | 短字段可并排；较长表单和解读仍用单列。牌阵可用紧凑网格。 |
| 1024 / 1180 宽平板横屏或分屏 | 以实际可用宽度为准；语言、登录和导航放不下时回到折叠菜单。 | 盘面与表单可并排。窗口缩窄时自然堆叠，旋转或改尺寸后保留用户已经填或选的内容。 |
| 1280 / 1440 以上桌面 | 主栏居中，左右入口共用基线。导航完整。 | 双栏工具可以把表单和盘面并排，长文和结果说明保持较窄的阅读宽度。 |

布局以视口和内容宽度判断，触摸与滚轮按输入能力分别处理。可点区按约 44px 的设计目标审查；鼠标悬停的信息要能用键盘和触屏取得。检查系统字号放大、320 CSS px 回流、可见焦点、菜单关闭后焦点返回、表单错误提示和屏幕阅读器可读的状态。参考 [W3C 回流说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

## 6. 实施顺序与验收

| 批次 | 实现范围 | 交给审核的证据 |
|---|---|---|
| A · 静态骨架 | 黑白主题、太极与导航、双入口、两个专厅首屏。用复用组件搭一条六爻和一条单张塔罗路径的界面。 | 中文及英文的桌面和手机截图。检查首屏文案、主次按钮、结果、键盘操作和链接直达。 |
| B · 首页交互 | 先用原生滚动跑通，接 ScrollTrigger，最后加入桌面 Lenis。 | 冷加载、上滑、回滑、点击跳转和返回的录屏。对照 Lenis 开关，试实际滚轮和触控板。 |
| C · 应用到其余页面 | 东方和塔罗工具、指南、账户、会员；补齐加载、错误、未登录、无数据和结果状态。 | 按 01–05 图稿编号提交对照。每类页面至少走通一个正常路径和一个关键异常路径，检查登录与积分行为。 |
| D · 发布前检查 | 中英文、路由、品牌元数据、生产性能。 | 构建和项目现有校验结果，移动真机记录，以及改版前后的网络瀑布与交互录制。 |

- **性能验收**：同一设备与网络条件下用生产构建跑冷加载对比，分别记录首页、六爻、自由抽牌与牌义详情。检查首页冷启动没有整副牌、抽牌工作台和其他工具脚本；普通落地页没有首页动画增量。查看上滑、选牌和提交时的主线程、长任务与布局偏移。Lenis 在收益不明确或出现稳定回退时保留原生方案。
- **现场指标**：有线上数据时，移动和桌面分别以第 75 百分位评估，目标 LCP ≤ 2.5 秒、INP ≤ 200ms、CLS ≤ 0.1。生产构建的本地录制用于对比，实际用户 INP 以现场数据为准。[Web Vitals 官方说明](https://web.dev/articles/vitals)
- **功能矩阵**：iOS Safari、安卓 Chrome、平板 Safari、桌面 Chrome / Edge 及 Safari 可用时检查。覆盖首次打开、前进/后退、刷新、锚点、语言切换、深链接、横竖切换、减少动态效果、断网或接口失败。关注菜单与滚动不冲突、旋转不清空已填内容、旧页链接仍指向合适的页面。

## 7. 换电脑继续设计或实现

仓库交接分支为 **codex/yitatro-design-handoff**，入口是 **docs/design/yitatro/README.md**。在另一台电脑克隆同一仓库或更新现有克隆后，检出该分支即可查看方案和配图。

- **只做设计或评审**：复制整套目录，或下载并解压交接 ZIP。打开 README.md，五张图在同级 mockups 目录。静态图稿用普通图像查看器即可打开，所有图稿链接使用相对路径。
- **继续实现**：在另一台电脑打开同一 Git 仓库及交接记录指定的分支和提交。按现有锁文件安装依赖，需配置时参考仓库的 .env.example，在各自环境单独设置真实值。图稿、快照、验收记录可以随项目版本交接，密钥和本机环境文件留在各自设备。
- **记录最新进度**：同一份设计稿作为审阅基准。换电脑前记录设计稿版本、代码分支和提交号、已完成批次、测试环境和待核对项。通过已有仓库或共享渠道同步最新版本；对上一个人尚未同步的工作，先获取其文件或补丁再继续。
- **提交修改意见**：使用「图稿编号 / 页号 / 设备或宽度 / 变更 / 验收方式」定位。例：05 / 02 / 手机 390px / 两个英文入口都可见 / iPhone Safari 从太极上滑后复查。设计稿发生变化时同时更新本文件的相关规则，并给新版打包，避免另一台电脑拿到过期的截图。

本包附的是 PNG 审阅稿与规格。品牌、页面结构和主题已按当前讨论收口；本包记录的代码基线用于定位现有项目，具体实现进度以接手时的分支和提交为准。
