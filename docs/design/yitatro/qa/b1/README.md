# B1 · 首页滚动性能对照

决策：保留原生太极开屏、上滑与锚点。已撤回 GSAP ScrollTrigger 试验，不引入 Lenis。原生版与试验版均通过本机生产构建；撤回后已重新构建。试验以 `8152af5` 及当时的改版工作区为基线，正式站未发布此试验。

[八组对照结果](comparison.json)：Windows 本地 Chromium，生产构建、冷缓存、每个语言和宽度三次，手机和平板模拟 4 倍 CPU 降速，桌面不降速。计量脚本为压缩传输数据体字节；延迟和帧间隔报告组内中位数。测量时应用其他脚本仍可能在首滑窗口运行；样本较小，LCP 和输入时延波动明显，不能当作线上 Web Vitals。

| 项目 | 结论 |
|---|---|
| 首页 390／768／1440，中英文 | 各组冷加载 CLS 为 0。新增 ScrollTrigger chunk 没在首滑前请求。 |
| 首次滚动 | 新试验 chunk 17,665 字节 gzip（约 17.3 KiB），六个首页组均有此开销；六组中五组的帧间隔 P95 中位数增加。英文 390 组略有改善。 |
| 现有首屏脚本 | 旧首页的 `HeroFloatingCards` 和 `DailyDrawWidget` 已提前引入 GSAP 核心和整副牌数据；首页试验不解决这笔开销。 |
| 内页对照 | 六爻冷加载 CLS 为 0；英文自由抽牌 390 的两版组内中位数均为 0.7258，是原生版本就有的布局跳动，另行定位。 |

撤回后复测：中英文 390／768／1440 下，触滑或滚轮、键盘定位、从双入口进入专厅、直接打开 #portals 全部通过；无 JavaScript 与减少动态效果也可用。复现既有返回问题：键盘跳到 #portals 后进塔罗专厅，再按浏览器返回，地址正确但仍显示专厅；六组均复现。直接打开锚点正常。列入 B2 排查。

未测真机 Safari、跨设备网络、稳定的线上指标。下一批先从首页冷启动移出旧塔罗互动和整副牌数据，再决定是否值得恢复滚动动效。
