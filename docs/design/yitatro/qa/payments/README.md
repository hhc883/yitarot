# 地区支付与积分到账

- 价格页根据部署边缘传来的国家码选择支付地区：CN → 中国大陆/CNY，其他已识别地区（包括 HK/MO/TW）→ 国际/USD，未知 → 用户选择。中英文不参与地区判断；VPN 或旅行用户可以手选。该地区只是默认结账偏好，不是实名认证或授权依据。地区 API 返回 private, no-store。
- 价格与服务端金额校验共用目录。中国大陆走已配置的单一虎皮椒商户通道，手机跳转，支持二维码时桌面展示扫码；海外保留 Payhip 链接和注册邮箱对账。渠道缺配置时不显示可付款按钮。旧 Stripe 入口保留，但未在支付页新增一个供应商。
- 到账按订单、金额、币种及支付状态核验。国内和 Stripe 缺签名密钥时拒绝回调；数据库事务处理订单和账本，重复通知不重复入账。Payhip 对新交易匹配已验证的登录邮箱，不能用可编辑档案邮箱领款；原单全额退款按原账户扣回，部分退款、金额不符、优惠或非单件订单由人工对账。国内及独立 Stripe 退款不在本次自动扣回范围。
- 兑换码新格式为 YITA2，配置独立密钥才启用，数据库全局只允许兑换一次。旧格式已默认关闭；只有确认原码使用的是当前独立、未泄露密钥才可临时启用旧格式。若用过仓库公开默认值，请更换密钥并重新发码。

## 部署顺序

1. 在测试数据库执行 `supabase/migrations/20261125000001_payment_integrity.sql`，再安排生产数据库迁移与代码部署；新增函数只给 service_role。上线前先核对迁移时仍未支付的旧人民币订单。新回调不会自动认领缺币种与通道的旧国内订单，需按真实商户对账处理。
2. 按 [.env.example](../../../../../.env.example) 配置官方 HTTPS 域名、商户密钥和对应回调。Vercel 默认用 X-Vercel-IP-Country；仅当源站不能绕过 Cloudflare，且已启用 IP Geolocation 时，才设置 PAYMENT_GEO_SOURCE=cloudflare。生产需用真实大陆及境外网络确认识别。
3. 当前 Payhip 商品需与代码中的 USD 固定价一致。发布前用渠道测试环境确认实际出单、扫码/收银、通知与退款字段；若使用含税变化总价、优惠或想自动处理部分退款，先核对供应商返回字段和对账规则，再扩展。Payhip 当前按其官方 Webhook 共享签名规范验证，签名需与密钥同等保护，不应写入日志。

## 本地验收

- `node --test scripts/test-payment-region.mjs` 检查边缘来源、国家码和价格解析。定向 ESLint、TypeScript、生产构建复跑通过。项目既有 Next.js 安全提示仍需单独处理。
- 用隔离 PostgreSQL 执行原迁移与新增迁移，验证服务端专用权限、金额/币种/订单绑定、重复支付和退款、全局兑换，以及仅认已验证支付邮箱。
- 本地 Chromium 模拟中国大陆、美国、香港和未知地区，覆盖中英文及 320/390/1440 宽度、手动切换、国内支付待确认、Payhip 链接和 Stripe 验证失败保留回执。浏览器使用假账号和模拟支付响应；未请求真实支付、未触碰生产 Supabase、未部署。本地 HTTP 另外验证：三条回调缺少配置返回 503，未登录用户不能发起结账或兑换（401）。
